Ключевые подтверждения:

- Настоящие временные файлы SQLite: порядок, параметры SQL, rollback, partial, terminal и повторное открытие.
- Незавершённый pending при новом старте становится interrupted/RESTART, текст сохраняется.
- Окно выбирает последние завершённые пары своего ID в прямом порядке; полная история не обрезается.
- Advisor в настоящем HTTP-пути передаёт нужные роли/сообщения, а не только регистрируется в mock.
- История A отсутствует в запросе B; failed-попытка отсутствует в следующем prompt.
- Completed записан до доставки terminal клиенту; cancel сохраняет partial и освобождает lease/upstream.
- Повторное close старой lease не освобождает более новую.
- UI восстанавливает статусы, защищает переключение во время запроса, использует серверную историю и выдерживает недоступный localStorage.

## Домашнее задание — новая самостоятельная задача

База из лекции, SQLite, memory advisor и UI предоставлены готовыми. Новое задание — поиск в сохранённом журнале своего conversationId: буквальное Unicode-сопоставление, terminal-only, новые результаты первыми, limit. Единственный TODO — `HistorySearch.find`; SQL и память менять не требуется.

- JavaScript: все **60 зелёные**.
- Основной и тестовый код компилируется; пропусков и отключённых тестов нет.

В отдельной временной копии реализован только `HistorySearch.find`, тестовые исходники не менялись: **87 Java + 60 JS зелёные**. Эталон в homework не включён. Новые проверки используют настоящий временный SQLite-файл, проверяют неизменность snapshot и memory window, изоляцию диалогов и HTTP endpoint. Поиск читает snapshot небольшого локального журнала; индексирование и пагинация больших историй остаются за пределами задания.

## Браузер и повторный запуск

Упакованный Java-проект работал с собственным локальным HTTP-stub Ollama и отдельным временным SQLite-файлом.

Проверены создание двух диалогов, сохранение первого обмена, передача контекста следующему запросу, отсутствие чужого имени во втором диалоге и восстановление первого при переключении. Контролы переключения блокировались на время потока. JavaScript-ошибок в проверочной вкладке не обнаружено.

Во время длинного ответа отдельный тестовый Java-процесс был аварийно остановлен и запущен снова с тем же SQLite-файлом. После reload восстановлены список, выбранный ID, завершённые пары и partial со статусом «Прерван». Следующий запрос использовал завершённые пары и не включал interrupted-попытку.
