# Урок 2.2. Документы, чанки и embeddings

Подготовим документацию учебного проекта TaskShelf для поиска в RepoPilot: разобьём файлы на фрагменты, сохраним их происхождение и получим векторы отдельной embedding-моделью. Результат — воспроизводимый снимок индекса; подключать поиск будем в следующем уроке.

## Что вы освоите

- Сравните разбиение фиксированным окном и по Markdown-разделам, сохранив файл, строки и hash каждого чанка.
- Подключите embedding-модель, проверите её профиль и размерность векторов.
- Опубликуете целый снимок индекса и переиспользуете его при неизменных входных данных.

## Домашнее задание

После изменения корпуса не обязательно вычислять все embeddings заново. Реализуйте `IncrementalEmbeddingPlanner`: определите, какие векторы можно переиспользовать по точному входу encoder, какие нужно получить заново и какие устарели.

Базовый pipeline уже готов. Совместимость профилей и правила сравнения заданы в [README ДЗ](homework/README.md); свои проверки и выводы внесите в [SUBMISSION.md](homework/SUBMISSION.md).

## Проверка

Нужны JDK 25 и Node.js 24. Каждый блок выполняется независимо из папки `lesson-2.2`.

Лекционный пример:

```bash
cd lecture
./mvnw test
npm ci
npm test
```

Домашнее задание:

```bash
cd homework
./mvnw -Dtest='*Test,!*HomeworkAcceptanceTest' test
./mvnw -Dtest=IncrementalReuseHomeworkAcceptanceTest test
npm ci
npm test
```

Первая Java-команда проверяет основу, вторая — новую политику после реализации. Для настоящей индексации подготовьте отдельную embedding-модель по [инструкции лекции](lecture/README.md).
