Интеграционные проверки запускают настоящее Boot-приложение и локальный HTTP-сервер с контрактом Ollama. Проверены:

- успешный путь `/api/chat` → Spring AI → Ollama-совместимый endpoint → ответ API;
- передача настроенного model ID, user message, `stream:false`, temperature и `num_predict`;
- преобразование provider HTTP 404 в безопасный HTTP 503;
- работа настроенного read timeout и отсутствие повторного provider-запроса;
- отсутствие обращения к provider при невалидном пользовательском вводе.

В выбранном Spring AI 2.0.2 `spring.ai.retry.max-attempts` передаётся в `RetryPolicy.maxRetries`. В примере стоит `0`; именно один запрос проверяется счётчиком HTTP-заглушки. Нельзя механически перенести сюда старое значение `1`, подразумевая отсутствие повторов.
