# ДЗ 1.2. Устойчивый браузерный черновик

[Материалы урока](../README.md) · [Лекция](../lecture/README.md) · [Приёмочные тесты](src/test/js/draft-acceptance.test.mjs) · [Отчёт по ДЗ](SUBMISSION.md)

## Чем задание отличается от лекции

Лекция дала Web UI, loading/error/success и HTTP-вызов. В этом проекте обычная страница `/` и весь backend **уже готовы**. Новая задача: пользователь возвращается после перезагрузки и видит несохранённый вопрос, а успешно отправленный черновик удаляется без потери более нового текста.

Для задания предоставлена отдельная страница `/draft.html` и готовый [draft-app.js](src/main/resources/static/js/draft-app.js). Реализуйте только три метода [draft-store.js](src/main/resources/static/js/draft-store.js). Переписывать chat-controller, view или fetch не требуется.

## Сценарий

1. Пользователь набирает вопрос на `/draft.html` — текст сохраняется в браузере.
2. После reload восстанавливается только поле вопроса, не выдуманная история ответов.
3. При успешной отправке удаляется именно отправленный черновик.
4. При ошибке модели вопрос остаётся для восстановления.
5. Если до очистки в storage уже записан другой текст, он сохраняется.

Черновик содержит текст вопроса в localStorage этого browser origin. Готовая страница сообщает об этом и содержит кнопку очистки. Это не серверная история и не шифрованное хранилище.

## Контракт

`createDraftStore(storage, key = "repopilot.draft.v1")` возвращает:

- `read()` → string. Прочитать JSON `{ "version":1, "text":"..." }`. Разрешён текст до 4000 JavaScript UTF-16 code units, включая пустую строку. Отсутствующие, испорченные, будущие версии и неверные типы дают пустую строку.
- `save(text)` → boolean. Сохранить только string длиной не больше 4000. Невалидный аргумент и недоступный storage дают false; успешная запись — true.
- `clearIfUnchanged(expected)` → boolean. Удалить запись только если валидная текущая запись v1 содержит ровно expected. Иначе вернуть false и ничего не удалять. После удаления вернуть true.

Ошибки getItem/setItem/removeItem не должны вылетать наружу. Присутствие `<script>` в черновике не означает HTML: храните и восстанавливайте буквальную строку.

Compare-and-clear — best effort: тест проверяет более новую запись, уже видимую **до** сравнения. Это не атомарная межвкладочная транзакция localStorage; полной координации вкладок данный срез не обещает.

## Проверки

```bash
./mvnw -DskipTests package
./mvnw test
npm ci
npm test
node --test src/test/js/draft-acceptance.test.mjs
```

Обычные UI/API regression-тесты проверяют готовую основу. Приёмочные сценарии охватывают versioned storage, запрет oversized/non-string, отказ storage, compare-and-clear, reload и сохранение вопроса после ошибки. Дополнительная regression-проверка готового binding подтверждает, что даже исключение при доступе к getter localStorage не ломает отправку вопроса. Реализуйте методы draft-store.js, затем выполните приёмочные проверки и весь набор Java/JavaScript без изменения условий тестов.

## Ручная проверка

Откройте `/draft.html`, напечатайте вопрос и перезагрузите страницу. Сравните успешную отправку и ошибку сети. Проверьте очистку и случай, когда storage заблокирован. На `/` не должно появляться регрессий.

Для проверки DOM достаточно HTTP-stub или unit transport. Только успешный реальный model request подтверждает настоящий inference; не смешивайте эти результаты.
