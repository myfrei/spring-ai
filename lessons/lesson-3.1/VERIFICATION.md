# Проверка урока 3.1

Дата: 2026-10-26. Java 25.0.5, Spring Boot 4.1.2, Spring AI 2.0.2. PostgreSQL с pgvector запускается Testcontainers; Ollama заменён локальным HTTP-сервером с фиксированными ответами.

## Рабочий пример

```bash
cd lecture
./mvnw -Ppgvector-it verify
npm ci
npm test
```

Результат: **191 Java + 16 pgvector IT + 104 JavaScript**, без ошибок и пропусков. HTTP-тесты вызывают настоящий Spring MVC/ChatClient; SQL-тесты используют настоящий PostgreSQL/pgvector. Весов LLM они не запускают.

Проверены: классификация evidence, контекстный бюджет, три синтетических случая, совместимость старых run-файлов, привязка trace к конкретной попытке, завершение trace, allowlist полей и отсутствие сырых вопроса/документа/ответа в диагностических логах и trace JSON. Отдельные IT проходят retrieval через SQL и генерацию через HTTP, включая пустой поиск и неверный ответ при доступном evidence.

UI диагностики наследуется в 3.2; там отдельно проверены открытие синтетической лаборатории и просмотр trace в браузере. [Снимок панели](../lesson-3.2/proof/diagnostics-inherited.png), [снимок trace](../lesson-3.2/proof/trace-inherited.png).

## Границы проверки

Синтетическая лаборатория не вызывает SQL или LLM и явно помечена `SYNTHETIC_LAB`. Она не заменяет измерения модели. Local trace инструментирует попытки experiment runner, а не каждый запрос чата; это не настроенный OpenTelemetry exporter. `GENERATION_REVIEW` означает повод исследовать ответ и ручную оценку, а не доказательство внутренней причины ошибки модели.

Качество ответов реальных локальных весов и скорость на компьютере студента остаются ручной проверкой по лекции и worksheet.
