# Урок 3.1. Найти причину плохого ответа

RepoPilot получает локальные trace стадий benchmark, безопасные структурированные логи и разбор «факт → гипотеза → эксперимент». Мы отдельно проверяем retrieval, окончательно выбранный контекст, ответ и цитаты. Контролируемый тренажёр воспроизводит три разных сбоя; реальные измерения модели остаются отдельным экспериментом.

- [Полная пошаговая лекция и рабочий проект](lecture/README.md).
- [Самостоятельное ДЗ: очередь ручного разбора](homework/README.md).
- [Бланк расследования двух случаев](lecture/evaluation/Failure-Investigation.md).
- [Проверки и ограничения](VERIFICATION.md).
- [Предыдущий урок 2.4](../lesson-2.4/README.md).
- [Следующий урок 3.2](../lesson-3.2/README.md).

`lecture` — готовое приращение к 2.4. В `homework` базовая диагностика тоже готова: студент добавляет отдельную политику triage, которая объединяет повторы, расставляет приоритеты и ограничивает результат после группировки. ДЗ не просит повторять классификатор лекции.

Для лекции начните с `cd lecture`, `./mvnw test`, `npm ci`, `npm test`. Полная проверка SQL/Advisor требует Docker: `./mvnw verify -Ppgvector-it`. Тренажёр можно открыть без Ollama/PostgreSQL, запустив приложение с `--repopilot.rag.enabled=false`; это SYNTHETIC_LAB, не измерение качества весов. Команды запуска настоящего RAG и API приведены в лекции.

Стек: Java 25, Spring Boot 4.1.2, Spring AI 2.0.2; новых библиотек относительно 2.4 нет. Local trace не является готовой интеграцией с OpenTelemetry. Категория GENERATION_REVIEW отмечает необходимость расследования и не доказывает внутреннюю причину ответа модели.
