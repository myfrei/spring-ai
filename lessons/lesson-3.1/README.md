# Урок 3.1. Найти причину плохого ответа

RepoPilot получает диагностику ответа: от найденных документов и выбранного контекста до генерации и цитат. Вы добавите журнал этапов запроса и тренажёр, на котором можно воспроизвести разные ошибки и проверить гипотезу о причине сбоя.

## Что вы освоите

- Отдельно проверять поиск, отбор контекста, ответ и ссылки на источники.
- Связывать этапы запроса через trace и записывать диагностические данные без текстов переписки.
- Разбирать ошибку по схеме «факт → гипотеза → одно изменение → повторная проверка».

## Домашнее задание

Добавьте очередь ручного разбора: объедините повторяющиеся проблемы, назначьте приоритет и ограничьте число групп в выдаче. Диагностика уже работает; ваша задача — помочь пользователю выбрать, какие инциденты расследовать первыми.

Условия и контракт `TriageQueue.build` находятся в [ДЗ](homework/README.md). Запишите решение и результаты проверок в [SUBMISSION.md](homework/SUBMISSION.md).

## Проверка

Нужны Java 25 и Node.js 24. Каждый блок запускается **отдельно из папки урока**.

Рабочий пример:

```bash
cd lecture
./mvnw test
npm ci
npm test
```

Каркас домашнего задания:

```bash
cd homework
./mvnw '-Dtest=*Test,!TriageQueueAcceptanceTest' test
./mvnw -Dtest=TriageQueueAcceptanceTest test
npm ci
npm test
```

После реализации ДЗ выполните `./mvnw test`. Для проверки полного RAG в выбранном проекте запустите `./mvnw verify -Ppgvector-it` с работающим Docker.

Подготовка моделей, индекса и запуск тренажёра описаны в [полной лекции](lecture/README.md). [Результаты проверки примера](VERIFICATION.md).
